# 오디세이 서바이벌 (Odyssey Survival)

뱀파이어 서바이벌의 게임플레이에 하데스의 내러티브를 얹은 모바일 로그라이크입니다.
TypeScript + Canvas 2D로 만들었고, Capacitor로 iOS / Android에 패키징합니다.

> A mobile roguelite survivors game: Vampire Survivors gameplay, Greek-myth
> narrative. TypeScript + Canvas 2D, packaged for iOS/Android with Capacitor.
> Korean / English / Japanese / Chinese.

---

## 직접 플레이해 보기

### 1. 폰에서 바로 (가장 쉬움)

`main`에 푸시되면 GitHub Actions가 자동으로 빌드해 GitHub Pages에 올립니다.
**최초 1회만** 레포 설정을 켜 주세요.

1. GitHub 레포 → **Settings → Pages**
2. **Source** 를 `GitHub Actions` 로 변경
3. **Actions** 탭에서 `Deploy to GitHub Pages` 가 초록불이 되면
   `https://<사용자명>.github.io/odyssey-survival/` 에서 바로 플레이할 수 있습니다.

폰 브라우저로 그 주소를 열고 "홈 화면에 추가"를 하면 주소창 없이 전체화면으로 뜹니다.

### 2. 내 컴퓨터에서

```bash
npm install
npm run dev -- --host      # 예: http://192.168.0.10:5173
```

`--host` 를 붙이면 같은 와이파이에 있는 폰에서 터미널에 찍힌 주소로 접속할 수 있습니다.
데스크톱 브라우저에서는 WASD / 방향키로도 움직일 수 있고, 크롬 개발자도구의 기기
모드(⌘⇧M / Ctrl+Shift+M)로 폰 화면 비율을 흉내 낼 수 있습니다.

### 3. 프로덕션 빌드 확인

```bash
npm run build      # 타입 검사 + dist/ 생성
npm run preview    # http://localhost:4173 에서 dist/ 서빙
```

### 4. 실기기 네이티브 빌드

아래 **모바일 패키징** 절을 참고하세요. Android는 Android Studio,
iOS는 macOS + Xcode가 필요합니다.

## 게임 디자인

### 조작

화면 **아무 곳이나 드래그**하면 그 방향으로 이동하고, 영웅은 **나아가는 방향으로 자동
공격**합니다. 손가락이 닿은 지점이 스틱의 원점이 되고, 멀리 끌면 원점이 따라옵니다.
휴대폰에서 정확히 조준하기는 어렵기 때문에 전방 약 16° 안에 적이 있으면 공격이 그쪽으로
살짝 붙습니다(에임 어시스트). 조준은 여전히 "이동 방향"으로 하는 것입니다.

발밑의 화살표가 지금 쏘는 방향을 알려 줍니다.

### 영웅

| 영웅       | 무기          | 성격                               | 해금      |
| ---------- | ------------- | ---------------------------------- | --------- |
| 오디세우스 | 이타케의 활   | 긴 사거리, 관통, 표준형            | 처음부터  |
| 아킬레우스 | 펠리온의 창검 | 전방 광역 참격, 강한 넉백, 근접    | 350 골드  |
| 시지프스   | 영원의 바위   | 느린 관통 투사체 + 착탄 광역       | 900 골드  |
| 타나토스   | 죽음의 장막   | 조준 불필요한 지속 장판, 빈사 즉사 | 1600 골드 |

다중 사격(`atk_count`)은 영웅마다 다르게 해석됩니다. 활/바위는 투사체가 늘고, 아킬레우스는
참격이 좌우로 늘어나며, 타나토스는 **회전하는 낫**을 얻습니다.

### 보물상자와 카드

맵을 돌아다니면 **체력을 가진 보물상자**가 나타납니다. 공격으로 부수면 3장 중 1장을 고릅니다.

- **신의 축복** — 11주신 × 각 3종 × 3단계(아테나 아이기스만 4단계).
- **기본 공격 업그레이드** — 피해, 공격 속도, 사거리, 크기, 투사체 개수, 관통, 유도,
  치명타, 그리고 **신의 각인**.

**레벨업**은 별도로, 영웅 스탯 카드를 3장 중 1장 고릅니다.

### 신의 각인 (Divine Infusion)

`atk_infuse` 를 얻으면 기본 공격이 **당신이 모신 신의 힘을 입습니다.** 여러 신을
모셨다면 공격할 때마다 신이 번갈아 실리고, **투사체 색깔이 그 신의 색으로 바뀌므로**
무엇이 터질지 날아가는 동안 알 수 있습니다. 각 신의 각인 효과는 게임 안 **만신전**
화면에서 전부 읽을 수 있습니다.

### 만신전 (신 해금)

11주신 중 **아레스 · 아테나 · 헤르메스 · 가이아 · 포세이돈**은 처음부터 사용할 수 있고,
나머지는 골드로 모십니다. 모시지 않은 신의 축복은 보물상자에 **아예 나오지 않습니다.**

| 신         | 가격 | 결                                                        |
| ---------- | ---- | --------------------------------------------------------- |
| 하데스     | 500  | 처치 시 회복 · 파멸 각인 · 최후의 폭발                    |
| 아프로디테 | 700  | 약화 · 매혹 · 상심 폭발                                   |
| 제우스     | 900  | 사슬 번개 · 심판의 벼락 · 정전기 (각인은 **방사형 전기**) |
| 디오니소스 | 1100 | 흡혈 · 넝쿨 속박 · 체력이 높을수록 강해짐                 |
| 아르테미스 | 1400 | 치명타 · 달빛 유도 화살 · 치명타 광역                     |
| 데메테르   | 1700 | **빙결** · 빙결 특효 + 파편 · 경험치와 치유               |

만신전 화면은 상점이자 도감입니다. 사기 전에 그 신의 축복 3종과 각인 효과를 전부 읽을 수
있습니다 — 11주신짜리 판테온에서 깜깜이 해금은 그냥 복권이니까요.

### 별자리 (메타 진행)

항해가 끝나면 획득한 골드가 남습니다. 골드로 **별자리**를 이어 영구 강화를 삽니다.

핵심은 **신탁의 그릇**입니다. 처음에는 한 판에서 신의 축복을 **1종류**만 받을 수 있고,
골드를 모아 단계적으로 **2종 → 3종**까지 해금합니다. 그 외에 시작 체력, 피해, 이동 속도,
골드/경험치 획득, 부활 횟수, 상자 출현률, 시작 레벨을 올릴 수 있습니다.

### 난이도

적 체력은 `1 + 분^1.25 × 0.11`, 스폰 속도는 분당 구간별로 오릅니다. 5분마다 보스
(미노타우로스 / 케르베로스)가 등장하고, 25분까지 내러티브 이정표가 흘러갑니다.

## 프로젝트 구조

```
src/
  core/         엔진: 고정 timestep 루프, 드래그 입력, 카메라/렌더러,
                시드 RNG, 절차적 WebAudio 효과음, localStorage 세이브
  data/         콘텐츠 테이블: 영웅, 11주신, 축복 33종, 무기 강화 9종,
                레벨업 특성 11종, 별자리, 적/웨이브/보스 스케줄
  game/         시뮬레이션: 런 상태, 엔티티, 공간 해시, 전투/효과,
                로드아웃 계산과 카드 추첨, 캔버스 드로잉, 수익화 계층
  ui/           DOM 오버레이: 화면들, HUD, 런타임 생성 아이콘
  i18n/         ko / en / ja / zh 사전과 t() 런타임
tests/          Playwright 기반 스모크 · 플로우 · 소크 테스트
```

이미지 에셋이 하나도 없습니다. 영웅, 신의 문양, 카드 아이콘, 적, 이펙트까지 모두 런타임에
캔버스로 그리고 효과음도 WebAudio로 합성합니다. 덕분에 전체 번들이 gzip 50KB 수준이고,
모바일 웹에서 즉시 뜹니다.

애니메이션도 시뮬레이션이 이미 들고 있는 두 개의 시계로 만듭니다 — 이동 중에만 도는
`walkPhase`(걸음 흔들림)와 `attackProgress`(0이면 방금 휘두름, 1이면 다음 공격 준비 완료).
그림을 스프라이트로 바꾸고 싶다면 `src/game/render.ts` 의 그리기 함수만 갈아끼우면
됩니다. 시뮬레이션은 렌더러를 전혀 모릅니다.

### 콘텐츠 추가하기

- **새 축복**: `src/data/boons.ts`에 항목 하나를 추가합니다. 이름/설명은 `L(ko, en, ja, zh)`로
  네 언어를 같이 적고, `apply(out, level)`에서 `out.stats` / `out.mech`를 건드립니다.
  `apply`는 "그 레벨을 보유한 상태의 전체 효과"이며, 카드를 얻을 때마다 로드아웃을 처음부터
  다시 계산하므로 값이 어긋날 일이 없습니다.
- **새 메커니즘**: `src/game/stats.ts`의 `Mechanics`에 숫자 필드를 추가하고(0 = 꺼짐)
  `src/game/run.ts`에서 읽습니다.
- **새 신**: `src/data/gods.ts`에 색·가격·각인 설명을, `src/data/boons.ts`에 축복 3종을,
  `src/ui/glyph.ts`에 문양을 추가하면 만신전에 자동으로 나타납니다.
- **새 영웅**: `src/data/heroes.ts`에 정의를 추가하고, 새 무기 타입이면 `Run.attack()`과
  `drawWeapon()`에 분기를 하나씩 추가합니다.
- **새 언어**: `src/i18n/`에 사전을 추가하고 `LOCALES`에 등록합니다. 사전은 한국어를
  기준으로 타입이 잡혀 있어 빠진 키가 있으면 컴파일에 실패합니다.

## 비즈니스 모델 (지금은 꺼져 있음)

수익화 코드는 완성돼 있지만 MVP에서는 **꺼둔 상태**입니다.
`src/game/monetization.ts` 의 `MONETIZATION_ENABLED` 하나로 상점 · 보상형 광고 부활 ·
결과 화면 골드 2배가 전부 켜지고 꺼집니다. 꺼져 있어도 코드는 그대로 컴파일·타입 검사되므로
방치되는 동안 썩지 않습니다.

붙일 때가 되면 게임 코드는 건드리지 않고 두 개의 구현만 갈아끼우면 됩니다.

```ts
// src/app.ts
this.money = new Monetization(
  new AdMobProvider(), // AdProvider 구현 (@capacitor-community/admob)
  new RevenueCatBilling(), // BillingProvider 구현
  () => this.save,
  () => this.commit(),
);
```

- **보상형 광고** — 상점에서 하루 5회까지 골드, 사망 시 1회 부활, 결과 화면 골드 2배.
- **인앱 결제** — 골드 꾸러미, 광고 제거(보상 2배), 영웅 전원 즉시 해금.

`AdProvider`는 `isReady(placement)`와 `showRewarded(placement)`만 만족하면 되고,
`showRewarded`는 **보상을 실제로 받았을 때만** `true`를 돌려줘야 합니다.
`BillingProvider`는 `isAvailable()`, `list()`, `purchase(id)`, `restore()`를 구현합니다.

## 모바일 패키징 (Capacitor)

```bash
npm run build
npx cap add android      # 최초 1회
npx cap add ios          # 최초 1회 (macOS + Xcode 필요)
npm run cap:android      # 빌드 + 동기화 + Android Studio 열기
npm run cap:ios          # 빌드 + 동기화 + Xcode 열기
```

`capacitor.config.ts`에 앱 ID(`com.odyssey.survival`), 배경색, `webDir: 'dist'`가 있습니다.
네이티브 프로젝트에서 추가로 손볼 것:

- **세로 고정** — Android는 `android/app/src/main/AndroidManifest.xml`의 액티비티에
  `android:screenOrientation="portrait"`, iOS는 Xcode의 Deployment Info에서 Portrait만 체크.
- **노치 대응** — CSS에 `env(safe-area-inset-*)`가 이미 적용돼 있고, `index.html`에
  `viewport-fit=cover`가 들어 있습니다.
- **진동** — 현재 웹 `navigator.vibrate`를 씁니다. iOS에서는 동작하지 않으므로
  `@capacitor/haptics`로 교체하는 것을 권장합니다.

## 테스트

세 개의 Playwright 스크립트가 있습니다. 전부 실제 브라우저에서 게임을 **직접 플레이**합니다.

```bash
npm run build && npm run preview     # 다른 터미널에서

npm run test:smoke   # 폰 크기로 한 판 플레이 → 상자 파괴 → 카드 선택 → 일시정지
npm run test:flows   # 네 영웅 전투, 사망→결과, 부활, 별자리 구매, 신 해금, 언어 전환
```

```bash
npm run dev                          # 다른 터미널에서
npm run test:soak    # 네 영웅을 각각 25분(시뮬레이션 시간) 빨리 감아
                     # 난이도 곡선, 보스 스케줄, 카드 풀, 신 개수 제한 검증
```

소크 테스트는 렌더링 없이 시뮬레이션만 빨리 감는 개발용 훅(`window.odyssey.simulate`)을
쓰기 때문에 **개발 서버에서만** 동작합니다. 프로덕션 번들에는 포함되지 않습니다
(빨리 감기 치트가 되기 때문입니다).

`OUT=./shots npm run test:smoke`처럼 `OUT`을 주면 각 단계의 스크린샷을 남깁니다.
CI(`.github/workflows/ci.yml`)는 매 PR마다 타입 검사 · 빌드 · 스모크 테스트를 돌립니다.
